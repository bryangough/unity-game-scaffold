## Ground rules

1. **Fixes before content.** The next item is a bug or a behaviour fix unless __OWNER__ asks for content.
2. **Levels are data**; the scene is generated by `__GAME__ > Build Main Scene`. A new level never needs a new scene.
3. **One new rule every ten levels, never a new verb.** The base game must be fun for ten levels first.
4. **Every level must be winnable**, checked by a tool, and must *need* its rule (a level that wins without the thing
   it introduces is not teaching it).
5. **Input System only.** No `UnityEngine.Input`; every input is an action on `GameInput`. Touch first; keys and a
   pad also work.
6. **Rules live in the rules class** with EditMode tests; MonoBehaviours only present them.
7. **The screen reads at a glance**: from the first frame the player sees everything that matters.
8. **Verify before hand-off:** compile clean, scene rebuilt from its menu, tests green, the changed levels played to a
   win and a loss, `R` restarts. Commit per task, `type(phaseN): summary`. Never run Editor commands while __OWNER__
   is in Play mode.

## The bar (every task is judged against it)

- One tap from the menu to the next unsolved level, one tap to retry.
- A level takes one to three minutes and can be put down at any moment; progress is saved per level.
- A new rule is taught by its first level, never by a paragraph.
- A loss is always the player's fault, and they can see why.
- Nothing to sign in to; the game always plays offline. No ads and nothing collected by default (a slot is kept,
  5.12; the decision is 6.4).
- Extras (stars, unlocks, settings) never sit between the player and the next level.
